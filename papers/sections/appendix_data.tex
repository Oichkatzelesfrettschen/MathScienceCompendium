\chapter{Data Inventory, Provenance, and Reproduction Notes}
\label{app:data_inventory}

This appendix documents every data artifact used in the compendium:
where each file lives, how it was generated, its SHA-256 digest (as of
last \texttt{make repro-refresh}), and the commands needed to reproduce it
from scratch.  The canonical provenance record is
\texttt{data/external/PROVENANCE.json}, which is regenerated automatically
by \texttt{make fetch-all}.

\section{Schema Definitions}
\label{app:schemas}
% ==============================================================================

Three JSON Schema files govern data structure validation:

\begin{enumerate}
    \item \textbf{\texttt{schemas/corpus\_document.schema.json}}:
          Validates each entry in \texttt{data/normalized/}.
          Required fields: \texttt{id}, \texttt{title}, \texttt{source\_path},
          \texttt{word\_count}, \texttt{sections}.
    \item \textbf{\texttt{schemas/provenance\_record.schema.json}}:
          Validates each entry in \texttt{PROVENANCE.json}.
          Required fields: \texttt{id}, \texttt{sha256}, \texttt{size\_bytes},
          \texttt{fetched\_at\_utc}, \texttt{source\_url}, \texttt{status}.
    \item \textbf{\texttt{schemas/artifact\_entry.schema.json}}:
          Validates figure and result registry entries.
          Required fields: \texttt{artifact\_id}, \texttt{path},
          \texttt{generated\_by}, \texttt{sha256}, \texttt{timestamp}.
\end{enumerate}

Schema validation is run by \texttt{make verify-offline}:
\begin{verbatim}
python -m jsonschema -i data/external/PROVENANCE.json \
    schemas/provenance_record.schema.json
\end{verbatim}

\section{Simulation Results Inventory}
\label{app:results_inventory}
% ==============================================================================

Simulation outputs are stored as Apache Parquet files under
\texttt{results/}.  Each file is registered in
\texttt{data/registry/simulation\_registry.toml} with:

\begin{itemize}
    \item \texttt{run\_id}: UUID of the simulation run,
    \item \texttt{scenario}: \texttt{"A"} (E7 forcing), \texttt{"B"}
          (E8 forcing), or \texttt{"C"} (comparison),
    \item \texttt{grid}: e.g., \texttt{"256x256"} or \texttt{"512x512"},
    \item \texttt{steps}: number of LBM steps,
    \item \texttt{sha256}: SHA-256 of the Parquet file,
    \item \texttt{generated\_at}: ISO-8601 timestamp,
    \item \texttt{git\_commit}: commit hash of the code that generated it.
\end{itemize}

\begin{verbatim}
# View simulation registry:
cat data/registry/simulation_registry.toml

# Re-run a specific scenario:
python -m mathphysics.main --scenario A --grid 256 --steps 1000
\end{verbatim}

\section{Provenance Requirements}
\label{app:provenance}
% ==============================================================================

Every external artifact must record:
\begin{enumerate}
    \item \textbf{Source URL}: canonical fetch location (arXiv, DOI, or
          commit-pinned mirror),
    \item \textbf{Retrieval timestamp}: ISO-8601 UTC,
    \item \textbf{File size}: bytes,
    \item \textbf{SHA-256 digest}: full 64-hex-character hash,
    \item \textbf{Local cache path}: relative to repository root.
\end{enumerate}

The \texttt{scripts/fetch\_external\_sources.py} script enforces these
requirements for all entries in \texttt{sources.toml}.

\section{Reproducibility Recipes}
\label{app:repro_recipes}
% ==============================================================================

\subsection{Full Clean Rebuild}

Starting from a fresh clone, reproduce all artifacts:

\begin{verbatim}
# 1. Install Python dependencies (pinned versions):
pip install -r requirements-lock.txt

# 2. Fetch all external PDFs:
make fetch-all

# 3. Extract text from PDFs:
make extract-text

# 4. Run all analysis modules:
make run-all

# 5. Generate all figures and explorer:
make figures

# 6. Compile the LaTeX document:
make papers

# 7. Verify checksums:
make verify-checksums
\end{verbatim}

\subsection{Docker-Based Reproducibility}

A fully reproducible environment is available via Docker:
\begin{verbatim}
# Build the image (Python + TeX Live + pdftotext):
docker compose build

# Run the full pipeline:
docker compose run --rm build make cleanbuild

# Run tests only:
docker compose run --rm test make test
\end{verbatim}

The \texttt{Dockerfile} pins Python, TeX Live, and system package versions;
see \texttt{Dockerfile} and \texttt{compose.yaml} in the repository root.

\subsection{Offline Verification}

To verify integrity of all cached artifacts without network access:
\begin{verbatim}
make verify-offline
\end{verbatim}

This checks:
\begin{enumerate}
    \item SHA-256 of all PDFs in \texttt{source\_materials/pdfs/} against
          \texttt{PROVENANCE.json},
    \item SHA-256 of all Parquet files in \texttt{results/} against
          \texttt{simulation\_registry.toml},
    \item JSON Schema validity of all normalized corpus records,
    \item That all \verb|\cite{}| keys in LaTeX source have entries in
          \texttt{references.bib}.
\end{enumerate}

\section{Corpus Text Extraction}
\label{app:corpus_extraction}
% ==============================================================================

PDF text is extracted using \texttt{pdftotext} (poppler-utils):
\begin{verbatim}
pdftotext -layout source_materials/pdfs/INPUTFILE.pdf \
    source_materials/pdfs/extracted/INPUTFILE.txt
\end{verbatim}

Extracted text files are then processed by the analysis pipeline and
stored as JSON corpus records in \texttt{data/normalized/}.

\subsection{Extraction Quality}

Known extraction issues:
\begin{itemize}
    \item Mathematical symbols may be garbled (use source PDFs for
          formula verification),
    \item Multi-column layouts may merge lines incorrectly (use
          \texttt{-raw} flag as fallback),
    \item Scanned PDFs (no embedded text) require OCR; not currently
          in the pipeline.
\end{itemize}
